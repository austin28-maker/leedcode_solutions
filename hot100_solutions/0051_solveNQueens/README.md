## 解题思路

- 回溯法
- 关键观察：n 行 n 个皇后且禁止同行 → 每行必有且只有一个皇后
- 问题转化为逐行决策：dfs(r) 表示"第 r 行的皇后放哪列"，行号 r 就是递归深度，天然免查"同行"冲突
- 决策树：每层枚举当前行的列 c（0 ~ n-1），不冲突则放置并进入下一行
- 冲突检查用三个布尔数组 O(1) 完成：
    - col[c]：列 c 是否被占
    - diag1[r + c]：主对角线（右上→左下方向），同一条线上 r+c 为定值，取值范围 0 ~ 2n-2，共 2n-1 条
    - diag2[r - c + n - 1]：副对角线（左上→右下方向），同一条线上 r-c 为定值，范围 -(n-1) ~ n-1，加 n-1 平移到非负下标
- 递归主体三步：做选择（queens[r] = c）→ 贴占用标签（三个数组置 true）→ 递归下一行 → 撤销标签（置 false）
- 出口 r == n：把 queens 数组翻译成棋盘，每行 char 数组 fill '.' 后在皇后列写 'Q'，new String(row) 转字符串收集

## 注意事项

- queens[r] 是覆盖写（下一轮直接盖掉），无需恢复现场；三个布尔数组是跨分支共享状态，必须显式恢复，否则误伤兄弟分支的冲突判断
- 对角线数量是 2n-1 条（不是 n），diag1/diag2 开 n * 2 - 1 长度
- r - c 可能为负，数组下标必须 +n-1 平移
- queens 数组本身已记录全部摆放信息，出口时才翻译成棋盘字符串，避免中途反复构造

## 知识点

- 回溯框架：做选择 → 递归 → 撤销选择（与 0078 子集、0131 分割同款）
- 覆盖写免撤销 vs 共享状态必须撤销的区分（0022 已总结过的法则）
- new String(char[]) 转换 + 快照语义（path 被后续覆盖不影响已收集答案）
- Arrays.fill(row, '.') 批量填充字符数组
- 时间复杂度 O(n!) 级（逐行可选列递减，剪枝削减常数不改变阶）；空间 O(n)（递归深度 + 标记数组，不计输出）

## 技巧

- 几何冲突代数化："同列"= 列号相同，"同对角线"= r+c 或 r-c 为定值 → 用代数式给每条线编号，冲突检查从扫描所有已放皇后（O(n)）降为数组查表（O(1)），称为增量标记
- 负数下标平移技巧：r - c 加 n-1 映射到 [0, 2n-2]
- "要求返回所有方案"的题目优先考虑回溯 + 剪枝
- 该增量标记思想可迁移：037 数独（行/列/宫标记）、079 单词搜索等冲突检测类回溯题通用

## 想不到的原因剖析

- Link 1（棋盘 → 逐行决策）：容易陷入"64 格挑 8 个"的组合爆炸视角；意识到"每行恰一个皇后"即可降维成"每行选一列"，识别分层结构是把指数问题变成回溯问题的关键
- Link 2（冲突检查 → 三个标记数组）：朴素做法是新皇后与已放皇后逐个比对；发现同行/同列/同对角线都是代数关系才能打表 O(1) 判断，这是本题唯一的新知识点
- Link 3：接受"穷举 + 剪枝"的大方向本身需要刷题积累直觉
