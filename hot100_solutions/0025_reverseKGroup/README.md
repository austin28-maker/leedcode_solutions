## 思路

该题解法并没有使用递归，而是使用迭代的方式实现的。

## 二编

- 难点一：边界条件的处理
    - 第一个边界条件：for循环里面的end != null
        - 如果链表的长度不足k个，直接返回头节点，表示不需要翻转。
        - 需要翻转的k个节点，要注意头节点和尾节点的处理。
        - 头结点：pre.next。
            - 之所以设计成pre.next，是因为要做k次循环，从pre开始遍历k次，遍历到的节点都作为本次需要翻转的节点
            - 开始的设计为pre = end = dummy
            - end最终遍历到第k个节点的位置，即end指向第k个节点
            - 接下来就是对这k个节点进行翻转reverse方法，详见反转链表的解法，很简单
            - 但是重点是要讲解边界条件的处理for(int i = 0; i < k && end != null; i++)
                - 这里的边界条件是end != null，因为如果end为null，说明链表的长度不足k个，不需要翻转。
                - for循环结束有两种情况，一种是正常结束，一种是因为end为null而结束。
                - 所以在for循环之后会有一个if(end == null)判断
                - 如果end为null，说明已经到了链表的末尾并且不足k个节点，不再需要重复翻转下去了，跳出整个的while循环
        - 尾节点点：end
            - 尾节点的设计需要注意：
                - end指向的是第k个节点
                - end节点在反转后成为了头节点
    
    - 第二个边界条件：while循环里面的end.next != null
        - 上面的for是为了单独一次的反转处理
        - 那么while循环就是将该翻转处理重复下去，直到end.next为null
        - 注意这里的end和for循环里面的end不一样
        - while循环中的end节点作为新一轮反转处理的前置准备，是指向待处理区域之外的，即指向的是已经翻转过的第k个节点的下一个节点
        - for循环中的end节点作为本轮反转处理的结束点，是指向待处理区域的最后一个节点
        - 这样就清晰了，while条件中的end.next为null，说明此时遍历到的节点已经到了链表的末尾，
        - 因为根本就没有节点了，而不是剩余节点不足k个

- 难点二：pre节点的理解
    - pre节点不仅仅作为当前需要翻转的链表的前一个节点，
    - 还作为上一轮已经翻转处理的最后一个节点，
    - 这样就方便了上一轮反转处理的最后一个节点的next指向的更新。

- 注意链表题目中有很多指向性节点的声明，
    - 例如本题中的start和next节点，这些节点和pre、end一样都是随着不同翻转链表区域的变化而变化的。
    - 理清节点的指向和更新，是解题的关键。

- 链表的常见操作之一：
    - 将一个节点的next节点暂存，这样就方便后续对当前节点的.next指向做调整，
    - 并且先前暂存的节点也会得到保留，而不是无法再次利用
