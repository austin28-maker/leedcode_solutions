# 75. 颜色分类（sortColors）

- 要求原地排序

## 题目简述

给定一个包含红色、白色、蓝色（分别用 0、1、2 表示）的数组，原地排序，使相同颜色相邻且按 0、1、2 顺序排列。要求不使用库函数，进阶要求一次遍历 + O(1) 空间。

## 解题思路

核心是"荷兰国旗问题"的经典解法：**三个下标把数组切成四段地盘**。

遍历过程中数组始终维持如下状态：

| 区间 | 内容 | 管理者 |
|---|---|---|
| `nums[0 .. p0)` | 全是 0 | `p0`：0 段右边界 |
| `nums[p0 .. p1)` | 全是 1 | `p1`：1 段右边界 |
| `nums[p1 .. i)` | 全是 2 | `i`：已处理右边界 |
| `nums[i .. 末尾]` | 还没看 | 待扫描区 |

每轮循环三步：

1. `x = nums[i]` —— 先把值**存下来**（下一步就要覆盖这个位置，不存就丢了）
2. `nums[i] = 2` —— 不管原来是什么，`i` 位置直接填 2（2 段向右扩一格）
3. 按 `x` 的值"补写"：
   - `x <= 1`：`nums[p1++] = 1`，1 段扩一格
   - `x == 0`：`nums[p0++] = 0`，0 段扩一格

## 最关键的细节：覆盖掉 1 为什么不出错

`x == 0` 时执行 `nums[p0] = 0`，该位置可能站着一个 1，分两种情况：

- **`p0 < p1`**（0 段与 1 段不重叠）：被覆盖的是旧的 1，但代码先执行了 `nums[p1++] = 1`，已把一个 1 补到更右边，相当于把那个 1 "往后推了一格"，一个不少。
- **`p0 == p1`**（两段无缝衔接）：覆盖掉的正是本轮刚写的 1。但 `x` 本身是 0，本轮不需要产出 1，顶掉正好。

## 注意事项

1. **两个 if 的顺序不能换**：必须先写 1 再写 0。否则 `x == 0` 时先写的 0 会被 `nums[p1++] = 1` 覆盖（p0 == p1 的场景）。
2. **必须先暂存 `x`**：`nums[i] = 2` 会立刻抹掉原值。
3. **`p0 <= p1` 恒成立**：0 段永远不会越过 1 段，无需额外判断或交换。
4. 别忘了 `p1++` / `p0++` 是后缀自增：先用旧值做下标，再移动指针。

## 知识点

- **荷兰国旗问题（Dutch National Flag）**：三路划分（3-way partitioning）的典型场景，也是快速排序三路优化（处理大量重复元素）的基础。
- **循环不变量（loop invariant）**：四段地盘的划分在每轮循环前后都保持成立，这是证明正确性的核心。
- **原地算法（in-place）**：只用常数个额外变量，直接在原数组上操作。

## 技巧

- **"直接覆盖"替代"交换"**：常见写法是遇到 0/1 时 swap 到前段；本解法利用"`i` 右边永远全是 2"这一性质，直接覆盖成 2 而不必保留原值，省去交换。
- **指针初始指向 0 且同向移动**：`p0`、`p1` 都从下标 0 出发向右走，不像对撞双指针那样需要分类讨论边界。
- **用区间端点理解指针**：把 `p0`/`p1` 理解为"已填好段的右边界（开区间端点）"而不是"某个元素的位置"，写法和边界都更清晰。

## 复杂度

- 时间复杂度：O(n)，只遍历一次
- 空间复杂度：O(1)，只用三个下标变量

## 练习建议

在纸上用短数组（如 `[2, 0, 1]`）手动推一遍每一步，重点观察 `p0 == p1` 时发生的事；推通后可尝试写出对撞双指针（`left`/`right`）版本作对比。
