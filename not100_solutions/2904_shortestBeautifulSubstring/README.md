## 解题思路

- 方法一：枚举右端
    - 如果 1 的个数不足 k，直接返回 ""
    - 否则，从长度为 k 开始枚举所有可能的子字符串，找到第一个符合条件的子字符串
- 方法二：滑动窗口
    - 初始化窗口大小为 k，左端为 0，右端为 0
    - 遍历右端，维护窗口内 1 的个数 cnt1
    - 当 cnt1 大于 k 或窗口内有 0 时，左端右移，维护 cnt1
    - 当 cnt1 等于 k 时，更新 ans 为当前窗口
    - 最后返回 ans

## 知识点

- compareTo 方法：用于比较两个字符串的字典序，返回值为负数表示第一个字符串小于第二个字符串，返回值为正数表示第一个字符串大于第二个字符串，返回值为零表示两个字符串相等

## 疑问点总结

- 为什么 i 从 size 开始？i 是"窗口的右端"，不是起点
    - substring(i - size, i) 是左闭右开区间 [i-size, i)，窗口长度恒为 size
    - i 最小取 size：此时窗口左端 i-size = 0，正好贴在串头；若 i 更小则左端为负，substring 抛 StringIndexOutOfBoundsException
    - i 最大取 s.length()：右端取 n 恰好取到最后一个字符（下标 n-1），这是左闭右开的红利——右端可以直接用 length，不越界
    - 对照 0131 的"枚举左端"写法 substring(start, i+1)：本题是"枚举右端"版本，边界数字更整齐（下界 size = 窗口长度，上界 n = 串长）

- 内层找到满足条件的子串为什么不直接 return？
    - 内层的任务不是"找到一个"，而是"同长度里字典序最小的"：长度条件由外层控制（size 从小到大，内层所有窗口同长），字典序条件必须横向比较所有候选
    - 反例：s = "10101", k = 2，size=3 时先遇到 "101"（合法），但后面还有 "010"（字典序更小，'0' < '1'），正确答案是 "010"；若找到就 return 会输出 "101"，长度对了但字典序不是最小
    - 所以 L16 的条件是 (ans.isEmpty() || t.compareTo(ans) < 0) && 1的个数==k：遇到更小的才换，必须扫完该长度的所有窗口才能定夺

- 提前终止在哪里？
    - 在内外层之间：外层 size 从小到大，第一个有解的长度就是最短长度，此时 ans 已是同长度候选中的最小者，立即返回（L21）
    - 分工：外层保证"最短"（有解即 return），内层保证"字典序最小"（扫完才停）

- 外层 for (int size = k; ; size++) 没写终止条件，会死循环么？
    - 不会，出口是内部的 return
    - 前提是开头的检查（1 的个数 ≥ k）保证了解的存在性：既然 1 的总数 ≥ k，一定存在某个窗口恰好框住 k 个 1，所以某个 size ≤ n 必有解，return 必然触发
    - "无限 for + 内部 return"是合法写法，但必须先证明"解一定存在"再这么写
